# Portable design principles

Use for Korean product copy or an open visual direction. These are this kit's defaults; explicit current product requirements take precedence. Keep existing design tokens and screen contracts. Read this file once per relevant task, not at every edit. It has no dependency on a personal computer or another product's files.

## 제품 문구

- 제품 하나에서 안내, 오류, 확인 문장의 말투를 통일한다. 업무 및 보고 도구는 습니다체를 기본으로 쓴다. 버튼과 항목 이름은 `초안 생성`, `변경 저장`처럼 행동이나 대상을 드러내는 짧은 표현을 쓴다.
- 직접 작성하는 한국어 제품 문구에서 `·`, `—`, `→`, 장식용 이모지로 문장을 이어 쓰지 않는다. 조사, 쉼표, 마침표로 읽히게 쓴다. 원문 인용, 데이터, 고유명사, 코드, 의미를 전달하는 도식의 기호는 보존한다.
- 제작 의도, 내부 처리 과정, 사용자의 요청을 화면에서 다시 해설하지 않는다. 지금의 행동을 바꾸는 조건, 저장 실패, 입력 유실 경고는 남긴다. `미저장`이나 `완료` 같은 단어 자체를 금지하지 않는다.
- 제목만 바꾸어도 이해되지 않으면 대상과 문맥을 바로잡는다. 예를 들어 버전별 응답 영역에서는 `받는 사람의 응답`이라는 제목 가까이에 어느 버전을 보는지 표시한다. 화면의 실제 역할에 맞춰 쓰고 이 예문을 고정 문구로 복사하지 않는다.

## 시각적 강조

먼저 위치와 여백으로 읽는 순서를 잡고, 필요하면 크기, 굵기, 표면과 테두리, 색을 차례로 검토한다. 상태의 의미와 접근성을 전달하는 색은 필요한 자리에서 바로 쓴다. 이 순서는 넓은 색 면으로 모든 문제를 풀지 않기 위한 선호이며, 특정 색이나 글자 크기를 고정하지 않는다.

## 판단과 참고 자료

- 작업을 가르는 판정 언어를 먼저 잡는다. 이미 받은 반응이나 실제 화면으로 `다음 할 일을 바로 찾는다`, `상태가 바뀌었는지 헷갈린다`처럼 관찰할 차이를 짧게 적는다. 정해진 개수의 목록이나 별도 승인 절차를 만들지 않는다.
- 참고 화면을 쓰면 가져올 관계 하나와 가져오지 않을 요소 하나를 현재 메모에 짧게 남긴다. 일하는 순서, 정보와 행동의 연결을 우선한다. 특정 제품의 색과 배치를 통째로 옮기지 않는다.
- 사용자가 승인하거나 표시한 캡처는 지정한 부분의 변경 기준으로 삼고, 당시 화면 상태와 범위를 보존한다. 캡처가 없는 동작이나 저장, 권한, 접근성까지 입증하지는 않는다. 캡처를 얻는 방법은 현재 환경의 제한을 따른다.
- 합의한 목적을 이루는 데 필요하지 않은 중간 화면, 안내 배너, 기능 투어를 임의로 추가하지 않는다. 필요한 오류 회복과 접근성은 구현 범위에 포함한다. 이미 위임한 사소한 결정마다 승인을 다시 받지 않는다.
- 같은 혼란이 반복되면 역할과 정보 관계를 다시 살핀다. 횟수를 세어 자동 재설계하지 않는다. 실제 동작과 문구는 제작 지침의 해당 절에서 검증한다.
