# Make a result the intended user can understand and use

Arrange evidence, actions and feedback around the person's actual purpose. Passive viewing and exploration may need orientation rather than a primary action.

For creation or redesign read `references/frontend-creation.md`; reuse it when already in context. Select other references only for a material decision. Keep the current task owner and existing product, accessibility, write-authority and release contracts. Planning does not authorize product edits. Platform restrictions govern observation and research even when a reference mentions a browser or screenshot.

## Composition and repair

Start with the actual path and content, so the first view works without the builder's coaching. Distinguish duplicate explanation from necessary information; preserve the purpose of anything removed. Keep internal identifiers out of ordinary copy unless they are genuine audience content.

References supply relationships whose conditions must fit. Compare coherent experiences for a whole-experience question and isolate a variable for a detail question. Use the project's existing matches before new research; `references/proven-expressions.md` explains how to preserve useful findings. Neither a candidate count nor a one-button quota is required.

Local defects call for local repair. If labels and repeated patches leave the same confusion, revisit the task model. Preserve explicit freezes, not every value of a comparison baseline.

## Evidence and completion

Use `references/frontend-creation.md` §9 for role-based observation, deferred checks and restricted environments. Observe changed properties and coupled behavior; builds and still frames prove only their measured properties. Protect explicit frozen items with the strongest meaningful available assertion, contract check, snapshot or named definition, recording source and date. Report protection gaps rather than treating prose promises as enforcement.

Use an independent observer when required or when first-reader comprehension can change acceptance. Give comprehension reviewers rendered evidence before rationale; goal reviewers also receive goals and constraints. Neither certifies taste. Honor checkpoints and stops; otherwise repair inspectable in-scope omissions and return a judgment-ready artifact with a recommendation.

## Apply the right reference without restarting the work

Inspect artifacts before research. State patterns help when loading, permissions or recovery affect the path; a full heuristic audit is not mandatory on every edit. Read the failure study only when it helps distinguish the current confusion.

`references/frontend-creation.md` takes precedence over an older specialist recipe. Specialist checklists cannot add universal quotas or approval gates. Project design rules take precedence over portable defaults; an authorized redesign may reconsider visual language. Images answer appearance questions, motion answers timing questions, and operation answers control questions, within allowed observation methods.

Return the artifact, observed behavior, meaningful gaps and required intent/Frozen items/Open variables references. The dispatcher handles in-scope correction before forwarding. Keep detailed commands in existing evidence; tell the user the result and real choices in ordinary language. Unknown is not failed, unperformed is not passed, and a narrow audit does not authorize redesign.
